# sovetnik-channel — мост сессий Claude Code в Telegram

Узкий гибрид из отчёта `tasks/20260414/REMOTE_CONTROL_RESEARCH.md` (корень проекта,
вне git-репозитория): голосовой ввод,
уведомления и одобрение разрешений идут через бота «Советник», а прерывание работы и
слэш-команды остаются за Remote Control (канал их не умеет — это ограничение протокола,
а не реализации).

```
Telegram (топик супергруппы)
    │  текст / голосовое
    ▼
бот «Советник» на VDS  ──── /cc/register, /cc/reply, /cc/permission, /cc/bye
    │  SSE /cc/stream                          ▲
    ▼                                          │
sovetnik-channel (stdio MCP на машине) ────────┘
    │  notifications/claude/channel
    ▼
сессия Claude Code (ваши файлы, ваши MCP-серверы)
```

Машины держат **только исходящие** соединения — портов на ноутбуках не открывается,
NAT и файрвол не мешают.

## Что уже сделано в коде

| Где | Что |

| `cc-channel/` | сам канал: MCP stdio + SSE-клиент (в образ бота не входит) |

## Установка

### 1. Супергруппа

Создать группу → в настройках включить **Темы (Topics)** → добавить бота «Советник»
администратором с правом **Управление темами**. Узнать id: временно добавить
[@RawDataBot](https://t.me/RawDataBot), взять `chat.id` (отрицательный, `-100…`).

### 2. Сервер бота

```env
CC_GROUP_ID=-1001234567890
CC_MACHINE_TOKEN=<openssl rand -hex 32>
```

Задеплоить. Миграция `0015` применится сама при старте. Без этих переменных `/cc/*`
отвечает 503, а middleware в боте не активируется — то есть мост просто выключен.

### 3. Каждая машина

```bash
cd voice-meet-planner/cc-channel
CC_HUB_URL=https://oauth.podbor-minuta.ru \
CC_MACHINE_TOKEN=<тот же токен> \
CC_MACHINE=mbp \
./install.sh
```

Скрипт соберёт канал и зарегистрирует MCP-сервер `sovetnik` на уровне пользователя.
Дальше — алиас в `~/.zshrc`:

```bash
alias ccx='claude --dangerously-load-development-channels server:sovetnik'
```

Флаг обязателен: кастомные каналы вне allowlist Anthropic, пока Channels в research
preview. Синтаксис флага может измениться.

## Как пользоваться

Запускаете `ccx` вместо `claude` — в супергруппе появляется топик `mbp · sovetnik`.
Дальше в этот топик:

- **текст** — уходит в сессию как `<channel source="sovetnik">`;
- **голосовое** — распознаётся вашим STT, эхо-транскрипт публикуется, текст уходит в сессию;
- **ответ Claude** приходит в тот же топик (через инструмент `reply`);
- **запрос разрешения** приходит с кнопками ✅/❌ — локальный диалог в терминале
  остаётся открытым, применяется тот ответ, что пришёл первым.

Топик создаётся один на пару «машина + рабочий каталог» и переиспользуется: сессии
живут минутами, а топики должны хранить историю. Если в одном топике сразу две живые
сессии, входящее уходит в **самую свежую**, а исходящие помечаются коротким id.

## Что мост не умеет — и не сможет

Ограничения протокола Channels, а не этой реализации:

- **нельзя прервать идущую работу** — события встают в очередь и доставляются на
  следующем ходу; аналога Esc нет;
- **нельзя слать слэш-команды** — содержимое приходит как тег в контекст, а не как промпт;
- **доставка не подтверждается** — если канал не загружен, событие теряется молча;
- нет `@`-автодополнения путей, прогресса subagents и вложений из приложения.

Всё перечисленное умеет Remote Control — поэтому он и остаётся основным способом
рулить сессией, а мост закрывает голос и уведомления.

## Безопасность

- Входящее принимается **только от `ADMIN_TELEGRAM_ID`** — проверка по отправителю,
  а не по чату: членство в супергруппе ничего не даёт.
- Машины авторизуются общим `CC_MACHINE_TOKEN` (сравнение constant-time), дальше
  каждая сессия работает по собственному одноразовому `sessionToken`.
- Кто может нажать кнопку в топике — тот одобряет запуск инструментов на трёх машинах.
  Не добавляйте в группу никого лишнего.
- Текст из Telegram попадает в сессию с доступом к `Bash` — это путь к RCE, если гейт
  ослабить. Не ослабляйте.

## Диагностика

| Симптом | Что смотреть |
|---|---|
| топик не создался | бот не админ группы или нет права «Управление темами» |
| `/cc/*` отдаёт 503 | не заданы `CC_GROUP_ID` / `CC_MACHINE_TOKEN` на сервере |
| `register failed: HTTP 401` | токены машины и сервера разошлись |
| канал не поднялся | `/mcp` в сессии; stderr в `~/.claude/debug/<session-id>.txt` |
| сообщения уходят «в никуда» | сессия запущена без `--dangerously-load-development-channels` |
